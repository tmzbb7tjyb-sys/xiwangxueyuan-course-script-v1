# 脚本包交接约定

按课程单元建立独立输出目录，保留输入原件。以下文件是“完整脚本与分镜”请求的默认交付；用户指定其他格式时可转换，但字段关系应保留。

| 文件 | 必要内容 |
|---|---|
| `brief.md` | 标题、受众、岗位时刻、学习结果与验收方式、选题取舍、片长与语速目标、视觉方向、资料版本。 |
| `evidence.md` | `E` ID、拟讲事实/规则/案例、来源定位、状态、适用范围、限制/冲突、需谁确认。 |
| `story-arc.md` | 开场问题、段落顺序、每段的学员追问、引入的信息位、判断如何改变、结尾工作动作与迁移练习。 |
| `narration.json` | 唯一的完整可朗读逐句文本；句 ID、顺序、读法、节奏提示、关联依据、状态。 |
| `storyboard.md` | 逐镜表；镜 ID、句 ID、教学作用、屏幕字、画面与变化、出现顺序、素材、依据、预估时长与审核状态。 |
| `handoff.md` | 文件清单及版本、预估时长区间、视觉/语速要求、素材需求、业务待确认问题、可制作范围与剩余风险。 |

## `narration.json` 的最小结构

```json
{
  "lesson_id": "creator-content-fit-01",
  "script_version": "1.0",
  "pace_target": "常规讲解的 1.5 倍；数字和关键判断放慢",
  "lines": [
    {
      "id": "L001",
      "order": 1,
      "text": "这个账号播放不错，报价也低，为什么还不能直接提报？",
      "pronunciation": [],
      "delivery": "在问题后留一个短停顿",
      "evidence_ids": ["E001"],
      "review_status": "ready"
    }
  ]
}
```

`text` 只放实际朗读的话，不含引号、时间码、舞台提示或“旁白：”。`pronunciation` 用于容易读错的数字、人名、缩写、品牌和术语；没有则为空数组。`delivery` 是演绎提示，不是音频参数。`review_status` 可用 `ready`、`pending_business_review`、`draft`。必要的未确认占位不能伪装成 `ready`。

## 逐镜表字段

| 字段 | 写法 |
|---|---|
| 镜 ID | `S001` 起，稳定且唯一。 |
| 句 ID | 一个或多个 `L` ID；多镜可共用一句，但要写清各镜对应的信息落点。 |
| 教学作用 | 此镜让学员看懂或改变什么判断。 |
| 屏幕文字 | 精简可读，不逐字搬运旁白。 |
| 画面与变化 | 对象、关系、前后状态和焦点；能看出为什么这样设计。 |
| 出现顺序 | 哪个元素先出现，跟哪句或哪个词同步；不写未经录音确认的精确时间码。 |
| 素材 | 已有文件及位置，或待制作/待授权的素材需求。 |
| 依据 ID | 画面与旁白涉及的 `E` ID；纯结构镜可注明“无事实主张”。 |
| 预估时长 | 区间及额外读屏/练习停留原因。 |
| 审核状态 | 可制作、待业务确认或草案。 |

## 一致性检查

1. `narration.json` 中 `L` ID 唯一、顺序明确、所有 `text` 连读后是一堂完整课。
2. 分镜引用的 `L` ID 均存在；每句至少有一个镜头承载。
3. 关键事实、数字、规则、真实案例的 `E` ID 在依据表中存在；画面新增的事实也要追溯。
4. 待确认项在依据表、句状态、镜状态和 `handoff.md` 中一致；不能交给制作端当定稿使用。
5. 预估时长包含旁白、气口、读屏、练习和必要过渡；制作端以实际音频重定时间码。

### 写法对比

弱： “原课件第 12 页提到，这个账号的 Vlog 数据不太好，所以我们要注意内容匹配。”

可用： “这次想做生活化植入，就要看它的 Vlog 表现。情感内容的爆款，不能替 Vlog 方案证明效果。”

弱： “我们要从用户需求出发，选择合适的达人。”

可用： “先问观众为什么看这个账号，再问这条合作内容能不能沿着同一个理由，让产品在具体场景里发挥作用。”
